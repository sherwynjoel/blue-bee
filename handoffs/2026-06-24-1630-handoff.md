## QC gate (recorded)
6-lens adversarial review (no-stub, state-machine, quote-math, write-scope, RBAC, idempotency/race) → each finding adversarially re-verified by an independent agent. **3 raw findings → 2 confirmed (1 blocker, 1 major), 0 minors. Both fixed + a fix-verify pass run.**
- **BLOCKER (idempotency)** — `IdempotencyInterceptor` cached the response fire-and-forget (`void redis.set` in `tap()`), so two **concurrent** same-key requests could both execute the handler → duplicate orders (the prior test only covered sequential replay). **Fixed:** a `SET…NX` **reservation lock** (`apps/api/src/common/idempotency.interceptor.ts`) — exactly one request reserves + runs; concurrent siblings see the reservation, wait for, and return the same cached body; the reservation is released on handler failure so a retry can proceed. Locked by a new concurrent-booking e2e + a live two-request demo (same id).
- **MAJOR (state-machine)** — `approve()` checked `expiresAt` outside the transaction, so a quote could expire between the check and the atomic claim and still be approved. **Fixed:** the claim's `WHERE` now includes an `expiresAt > now` guard (`apps/api/src/orders/quote.service.ts`); a claim that matches 0 rows re-reads to return a precise `409` (`quote_expired` vs `quote_not_sent`). Locked by a new expired-quote e2e.
