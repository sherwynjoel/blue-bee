## QC gate (recorded)
6-lens adversarial review (no-stub, §5.4 state machine, order-leg, sequencer, RBAC, idempotency/concurrency) → each finding independently re-verified. **11 raw findings → 8 confirmed blocker/major + 1 minor. All confirmed blockers/majors fixed + a fix-verify pass run.**
- **BLOCKER + 4 MAJORS + 1 MINOR (defense-in-depth orgId scoping)** — inside `prisma.$transaction`, the `tx` client does NOT inherit the scoped-prisma extension, so several `update`/`updateMany`/`count` writes lacked `orgId` in their WHERE (`route.service.ts` optimize/assign/startGeo-raw-SQL/addStop-aggregate; `route-stop.service.ts` patch reassign/resequence/timeWindow + `maybeStartRoute`/`maybeCompleteRoute`; `fleet.service.ts` vehicle update). **Fixed:** every in-transaction logistics write now carries `orgId` (matching the state-machine pattern); helpers gained an `orgId` param.
- **MAJOR (order-leg) — publish() not idempotent for an order on two pickup stops** → second apply on a now-SCHEDULED order would 409 and roll the publish back. **Fixed:** dedupe `Set<orderId>` so each order advances exactly once. Locked by a regression test.
- **MAJOR (concurrency) — addStop seq race** (concurrent auto-seq adds → 409 `SEQ_TAKEN`). **Fixed:** retry-on-collision loop recomputes `MAX(seq)+1` (explicit-seq collisions still 409).
- **MAJOR (concurrency) — optimize vs concurrent PATCH** could mis-sequence a stop moved off-route. **Fixed:** reseq `updateMany` scoped by `routeId` (a moved-away stop matches 0 rows).
- **MAJOR (idempotency, NOT a bug) — "interceptor caches 409s"**: does NOT apply to the hardened interceptor — thrown errors flow through RxJS `catchError`, which `del`s the reservation and rethrows, so error responses are never cached and a retry re-executes. Locked by a regression test (409 under a key, then a valid retry with the same key succeeds).
