### Shipped
- **Socket.IO gateway** mounted on the Nest HTTP server with the **Redis adapter** (`RedisIoAdapter`, cross-instance fan-out) behind a thin `RealtimePublisher` abstraction (Ably/Pusher swap-in later). Two namespaces, authorized at the handshake and **server-bound** (no client-driven subscribe):
  - **`/live/vehicle` (customer)** — `auth.token` = the signed channel token; bound to exactly one vehicle room + its stop room.
  - **`/live/fleet` (OWNER/DISPATCHER/CSR)** — `auth.token` = the access JWT (verified + revocation-checked + role-gated); bound to the caller-org fleet room (all org vehicles, org-scoped).
- **Signed channel token** — `GET /v1/orders/:id/tracking` now returns `{ lastKnown, channelToken }`. The token is a short-lived **dedicated-secret** HS256 JWT (`CHANNEL_TOKEN_SECRET`, never the auth JWT), `kind: 'vehicle-tracking'`, claims `{ org_id, vehicle_id, order_id, stop_id, sub, exp }`. At the WS handshake the server verifies signature+expiry+kind **and re-checks LIVE stop state** (route PUBLISHED/IN_PROGRESS, stop non-terminal, route still points at the bound vehicle) — so a token for a completed/failed/reassigned stop is useless even before `exp`.
- **Publish step** — ingestion publishes a position to the vehicle room + fleet room **only when the Lua-CAS advanced last-known** (`lastKnownUpdated===true`): monotonic, no regression on out-of-order pings, no duplicate storms.
- **Lifecycle teardown (no leak after delivery)** — a customer socket is force-disconnected on (1) token `exp` (per-socket timer, cleared on disconnect), (2) stop terminal transition (`closeStopChannel`, after the §5.4 tx commits), (3) shift end (`closeVehicleChannel`). Reconnect after any of these fails the live re-check.
- **Graceful degradation (§12.3)** — the WS is an optimization; the Inc-5 REST last-known (`GET /fleet/live`, `GET /orders/:id/tracking`) + status timeline remain the source of truth. `publishPosition` no-ops if the gateway server isn't bound (never fails the ingest request).
- **WS contract documented** in `ARCHITECTURE.md` (OpenAPI doesn't cover WS): namespaces, auth, `position` / `channel:closed` events, error codes, lifecycle.

**FIXED (blockers/majors + cheap minors):**
- **MAJOR — publish ordering under concurrent same-vehicle batches** (`ingestion.service.ts`): the emit replayed the batch-local `newest` after two `await`s, so two overlapping batches could deliver `T+30` then `T` on the wire (store stayed monotonic via the CAS; the stream didn't). **Fix:** emit the authoritative readback head, gated on `this batch is still the head` (`Date.parse(lastKnown.recordedAt) === newest.recordedAt.getTime()`) — a superseded batch skips its now-stale emit; stale batches (`lastKnownUpdated=false`) still never emit.
- **MAJOR — reassign privacy leak** (`route-stop.service.ts` `patch()`, self-verified): moving an actively-tracked stop to a route with a different vehicle left the customer streaming the OLD vehicle (no teardown). **Fix:** on a reassign that changes the vehicle, `closeStopChannel(..., 'stop_reassigned')` after the tx commits (new `ChannelClosedReason`); the customer disconnects and must re-mint (→ the new vehicle). Locked by a new e2e test.
- **MINOR — capability/JWT accepted via URL query** (`realtime.gateway.ts`): dropped the `handshake.query.token` fallback → **`auth.token` only** (no bearer credential in proxy logs / history / Referer).
- **MINOR — Redis pub/sub not closed on shutdown** (`main.ts`): quit `pubClient`/`subClient` on `beforeExit`.

**DOCUMENTED as justified minors** (hard invariants all hold — never another vehicle/fleet, forged/expired/cross-vehicle rejected, no reconnect after delivery; WS is an optimization with REST as source of truth):
- A single in-flight `position` frame for the SAME vehicle in a microsecond window after stop completion (teardown vs in-flight publish race) — transient, same-vehicle, self-healing; reconnect is blocked.
- TOCTOU between handshake auth-pass and room-join (same µs-window class).
- An open `/live/fleet` socket isn't torn down on access-token revocation — bounded by the 15-min access TTL + the per-socket exp-disconnect timer (staff channel, not customer privacy); live-revocation push is deferred to the notifications/realtime-control increment.
