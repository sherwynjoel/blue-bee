## What shipped (all real, no stubs)
1. **Trigger (degradation-safe).** `geofence.service.evaluate` now returns the NEWLY-written crossings;
   `TrackingPredictionService` hands them to `NotificationService.dispatchGeofence` — wrapped so a
   notification failure can NEVER fail `POST /locations:batch`, the geofence write, the ETA, or a §5.4
   transition. Only the DB enqueue is awaited on the ingest path; sending is off-thread (below).
2. **Engine (`notifications/`), pipeline per (recipient × channel):**
   - **Recipient resolution** (`notification-recipients.service.ts`) — the INVERSE of the Inc-6 read
     scope: owning-customer users hold a CUSTOMER-role grant (`RESIDENTIAL_CUSTOMER`/`ACCOUNT_ADMIN`/
     `ACCOUNT_STAFF`) scoped to the order's account (or site). Explicit `org_id`; never cross-account/org.
   - **§17.2 matrix as config** (`notifications.config.ts`, `NOTIF_MATRIX_*`) — geofence alerts default
     Push+SMS+Email; adding a row is data, not code.
   - **Preferences + quiet hours** (`NotificationPreference`, pure `notification-policy.ts` +
     `quiet-hours.ts`): opt-out → `SUPPRESSED`; non-urgent inside the window **deferred** to the
     window-end (DST-correct) or suppressed per `NOTIF_QUIET_HOURS_POLICY`; **urgent** events
     (`NOTIF_URGENT_EVENT_TYPES`) **bypass** quiet hours.
   - **Templates** (`notification-templates.ts`, EN) — "~5 min away"/"arrived" + order ref + driver name.
   - **Outbox + idempotency** (`notification.service.ts`) — one `Notification` row per
     **(event source × recipient × channel)**, unique `dedupe_key` + `INSERT … ON CONFLICT DO NOTHING`
     (the Inc-5 pattern; the second line of defense behind the once-per-stop `GeofenceEvent`).
   - **Processor** (`notification-processor.service.ts`) — sending is OFF the ingest request thread:
     dispatch ENQUEUES, then a drain (a background kick on enqueue + the prod `NOTIF_RETRY_SCAN_MS` scan)
     sends. Each row is **atomically claimed** (a conditional `updateMany` that leases `scheduled_for`
     forward) before sending → concurrent drains across instances never double-send. Bounded linear-
     backoff retry → `SENT | RETRYING | FAILED`; a per-attempt timeout bounds a hung provider; per-channel
     isolation; `attemptSend` never throws.
3. **Three real transports** behind `NOTIFICATION_TRANSPORTS`: **SMS** reuses the Inc-2 `SMS_TRANSPORT`
   (Twilio — no second client), **Email** = a real SendGrid v3 call (`SENDGRID_SANDBOX`), **Push** = a real
   Expo Push call (`PUSH_TRANSPORT=expo`). Each has a **real local "console" fallback** (the Inc-2 pattern:
   logs + synthetic id, NOT a mock) when creds are absent, so the engine runs end-to-end without provider
   accounts.
4. **Device registration** — `POST/DELETE /v1/device-tokens` (`DeviceToken`): register/deactivate a push
   token, strictly user-scoped, idempotent by token.
5. **Config-driven** (`config/notifications.config.ts` + `.env`/`.env.example`): matrix, urgent set,
   retry/backoff/timeout, scan interval, kick-on-dispatch, quiet-hours policy/tz, SendGrid sandbox/from,
   push selector. No literals. No new prod deps (SendGrid/Expo via global `fetch`).

## QC gate (6-lens adversarial + refute-by-default)
Parallel read-only subagents — 6 lenses (no-stub/transports · idempotency/dedup · recipient-scoping/privacy/
tenancy · preferences/quiet-hours · delivery-reliability/retry · degradation/integration), each refute-by-
default. **Lenses 1 (no-stub) & 3 (scoping) returned NO FINDINGS.** Findings: **1 blocker, 2 major, 1 minor —
ALL fixed + fix-verified:**
- *(BLOCKER, idempotency)* `attemptSend` had no atomic claim → concurrent multi-instance drains could
  double-SEND a retry/deferred row → added a **lease-claim** `updateMany` (Postgres row-locks + re-evaluates
  the WHERE on the leased row → exactly one sender). Locked by a concurrent-attemptSend unit test.
- *(MAJOR, degradation/latency)* inline transport sends were awaited on the ingest request thread (unbounded
  fan-out latency) → **decoupled send from ingest**: dispatch enqueues only; a background drain (kick +
  prod scan) sends. Ingest awaits only DB inserts now.
- *(MAJOR, quiet hours)* DST fall-back made a deferred non-urgent alert schedule INSIDE the window (sent ~1h
  early) → **DST-correct `quietHoursEndAt`** (iterative local-wall-clock convergence). Locked by a Nov-fall-back
  unit test.
- *(MINOR, reliability)* a DB-write inside the catch could throw out of `attemptSend` (aborting sibling
  channels) → `attemptSend` now fully wrapped (never throws) + the drain isolates each row.

Fix-verify: typecheck + production build clean; **125 unit + 78 e2e green**; no-stub sweep clean.
