## As-built ↔ PRD reconciliations (record them)
- **Slash routes, not colon.** The driver action routes use `/driver/stops/:id/depart` (slash sub-paths), not
  the ops `:action` colon style: the deeper 3-segment `:id\:action` pattern doesn't match under
  platform-express's path-to-regexp (the 2-segment ops ones do). The new surface uses the robust shape; ops
  endpoints are untouched.
- **`asOrgScoped` is safe.** The delegated ops call runs with the driver's principal widened to org-read-scope
  (userId/orgId preserved) ONLY AFTER the ownership gate — a read-scope widener, not a privilege grant. QC lens
  6 traced every predicate: no cross-driver, no cross-org path. e2e-locked.
- **POD + media/storage still DEFERRED.** POD (geo-photo + signature) + scan/tally wait on the **presigned
  media-upload/storage path outstanding since Increment 3** (no fake uploads). The customer app (Inc 10) will
  also need it. The **full offline-first queue** is deferred (only a basic location-upload retry buffer is in
  scope). In-app turn-by-turn is a native-maps hand-off.
- **Push receipt is the on-device step.** Registration + the Expo token path are real + proven; a push
  physically arriving needs a real device (Expo push can't reach a simulator).

## ▶ The on-device run (your step — the one thing this headless env can't do)
No simulator/emulator/device exists in the build env, so the UI render + OS background task + real push receipt
are yours to run. One command each:

```bash
# 0. infra + API + a fresh seed (host Postgres+Redis; the seed has DRIVER:+14165550006)
cd "Blue Bee" && npm run infra:up
cd apps/api && npx prisma migrate reset --force && npm run build && node dist/main.js   # API on :3000

# 1. set up a route for the driver (dispatcher/owner) — or just run the integration proof which does it:
cd ../driver && API_BASE_URL=http://localhost:3000 npm run integration   # 15/15 green = backend ready

# 2. launch the app
#    iOS simulator:  npm --workspace @blue-bee/driver run ios
#    Android emul.:  npm --workspace @blue-bee/driver run android
#    PHYSICAL device (Expo Go): npm --workspace @blue-bee/driver start  — then set the API base to your LAN IP:
#      EXPO_PUBLIC_API_BASE_URL=http://<your-LAN-ip>:3000 npm --workspace @blue-bee/driver start
```
Then in the app: log in as `+14165550006` (the dev OTP is printed in the API console) → **Start shift** (grant
location "Always" + see the sharing indicator) → drive/simulate movement → confirm pings land
(`GET /v1/fleet/live` or the customer `GET /v1/orders/:id/tracking`) → open the route → walk a stop
depart→arrive→start→complete (and try a fail-with-reason) → confirm the device registered a push token.
**Real push receipt:** with `PUSH_TRANSPORT=expo` + a real device token, trigger a geofence (drive to the stop)
for an order whose owning customer is logged in on a device — the engine sends a real Expo push that the device
receives (this closes Inc-8's deferred real-device push). Notes: a PHYSICAL device is required for a real Expo
push token (simulators return none); on a device set `EXPO_PUBLIC_API_BASE_URL` to the host LAN IP.
