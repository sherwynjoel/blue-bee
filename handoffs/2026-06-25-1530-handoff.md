## What shipped
- **The storage seam (`@Global StorageModule`).** `StorageProvider` = `presignPut`/`presignGet`/`head`/`delete`,
  the ONLY AWS-SDK touch-point; one `S3StorageProvider` serves prod **AWS S3** and local/test **MinIO** (selected
  by `S3_ENDPOINT` + path-style) from the same code. A `MediaSigner` mints signed GETs (global → no import cycle).
- **`POST /v1/media/presign`** — authorizes the target via the proven `OrderAccessService` (caller must own the
  order/item), validates content-type (allow-listed, signed into the PUT) + size, mints an org-namespaced
  unguessable key `org/{orgId}/{kind}/{uuid}.ext`, records a **PENDING `MediaUpload` intent**, returns a
  short-lived presigned PUT URL (with **ContentLength signed** → oversize rejected at the S3 edge).
- **`POST /v1/media/confirm`** — loads the intent (same-org proof the caller presigned this key), re-authorizes,
  **`head()`-verifies the real object** (exists + content-type + size match; a bad object is deleted), creates the
  `Photo` with the key, flips the intent `CONFIRMED`. Idempotent on the unique `storage_key` (incl. concurrent).
- **Signed expiring reads (§14):** `Photo` stores the KEY; every read mints a fresh short-lived presigned GET
  (`OrdersService.signOrderPhotos` strips the raw key → `downloadUrl`).
- **Migration `20260625120000_media_storage_inc10`** (additive, reversible): `Photo.+storage_key(unique)/`
  `+content_type/+size_bytes`, `url`→nullable (legacy fallback); `MediaUpload` intent table; `POD.+signature_key`.
- **Intake retrofit:** booking no longer takes `photoUrl`; the `…/items/:itemId/photos` register-a-URL endpoint
  is retired; §5.1 damage evidence is now a `damagePhotoId` (a Photo uploaded via `/media`); old `orders/media.ts`
  deleted. MEDIA_ALLOWED_ORIGINS kept only as a documented external-reference fallback.
