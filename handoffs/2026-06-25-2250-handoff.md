## What shipped

### `packages/api-client` (NEW) — the no-duplication seam
The genuinely app-agnostic transport+session, extracted so **both** apps import it (the architecture call):
- **`ApiClient`** — `fetch` transport + injectable `TokenStore` + single-flight `401 → /auth/refresh →
  retry` + `problem+json → ApiError`; `request` is `protected` (apps subclass it) and accepts an
  `idempotencyKey` (→ `Idempotency-Key` header). Carries the shared auth surface (`requestOtp`/
  `verifyOtp`/`me`/`logout`) + device tokens (`register`/`unregister`).
- **`ApiError`/`ProblemDetails`**, **`TokenStore`/`MemoryTokenStore`**, and **`useAuthSession`** (the
  headless auth lifecycle: hydrate-on-launch, OTP/login, logout-even-offline, `onSignedIn`/`onSignOut`).
- **Pure entry — no native imports** — so it loads under Node for the integration proofs. Each app keeps
  its own native `SecureTokenStore` (expo-secure-store). Built to `dist` (CommonJS) like `@blue-bee/shared`;
  apps' jest map `@blue-bee/api-client` → `dist`, turbo `^build` builds it first. 7 unit tests.
- **`apps/driver` refactored to consume it** — `src/api/{problem,token-store}.ts` are thin re-export
  shims, `src/api/client.ts` is a `class ApiClient extends BaseApiClient` adding only `/driver/*` +
  `/locations:batch`, and `SessionProvider.tsx` now layers driver state on `useAuthSession`.
  **Driver stays green: typecheck + lint + 18 tests + `expo export` all pass — no regression.**

### `apps/customer` (Expo SDK 51) — wired into npm-workspaces + Turborepo
- **Login** — phone OTP → keychain → `/me` (the shared `useAuthSession`, single long-lived client via `useRef`).
- **My orders** — `GET /v1/orders` (row-scoped — the customer sees only their own).
- **Book** — `POST /v1/orders` with a real `serviceId`/`siteId` (from the new catalog reads), shows the
  returned rough estimate range; a stable `Idempotency-Key` per submit → a timeout/retry never double-books.
- **Order detail** — the **§5.1 status timeline rendered from `order.status`** (pure `buildTimeline`,
  never invented); the **quote** with **approve / decline** (`/orders/:id/quote:approve` /
  `quote:decline` — the as-built **colon** routes), server-authoritative + atomic → a 409 (expired /
  already-claimed) **re-syncs to server truth, never fought**; the **pre-existing-damage** ack notice +
  the damage photo; the order's photos via **signed `downloadUrl`** (raw key never exposed); a
  **"Track my truck"** entry when there's an active stop.
- **Track-my-truck** — `GET /orders/:id/tracking` → connect `WS /live/vehicle` (`socket.io-client`,
  token in **handshake auth**) on a `react-native-maps` map + ETA range + approaching/arrived. A
  framework-agnostic `TrackingController` (unit-tested) enforces the **§12.3 contract**: REST is the
  source of truth; a **dead/expired token** (`channel:closed{token_expired}` or a handshake
  `connect_error stop_not_active`) **re-fetches `/tracking` for a fresh token + reconnects** (bounded);
  `channel:closed{stop_completed|stop_reassigned|…}` → re-fetch (a new active stop reconnects, else
  **degrade to REST last-known + the timeline**); a dropped socket → degraded (auto-reconnect) — **never
  a blank screen, never an invented position**. Foreground-only (no background-location task).
- **Before/after + condition photos** — `expo-image-picker` → `POST /media/presign` → **PUT real bytes**
  (`expo-file-system` binary upload, the signed `Content-Type`) → `POST /media/confirm`; view via the
  signed `downloadUrl`. Client validates content-type + size against the server allow-list **before**
  presign **and** re-checks the presign `maxBytes`.
- **Push** — `expo-notifications` token → `POST /v1/device-tokens`; a tapped geofence push **deep-links
  to that order's tracking**, scoped (the engine only sends the owning customer the push; the screen
  reads through the scoped API → a non-owned id 404s).
- **54 unit/component tests** (extracted client single-flight, booking→DTO + idempotent retry, quote
  approve/decline + 409 re-sync, the tracking controller — token-expiry/channel:closed/REST-degrade/
  privacy, media presign→PUT→confirm + allow-list, push deep-link extraction, timeline from server
  state, login + order-detail render). **`expo export` bundles (Hermes, 959 modules).**

## As-built ↔ prompt reconciliations (the code won)
- **Quote approve/decline are COLON routes** (`/orders/:id/quote:approve` / `quote:decline`), not slashes
  — the existing Inc-3 controller declares the escaped colon. (The Inc-9 path-to-regexp lesson is for NEW
  routes; the new catalog reads use slashes.)
- The **customer role is `RESIDENTIAL_CUSTOMER`**; only it (among customer roles) may **book**, while
  `ACCOUNT_ADMIN`/`ACCOUNT_STAFF` may also approve/decline.
- The tracking read field is **`vehicle`** (LastKnownPosition), not `lastKnown` (ARCHITECTURE prose).
- `channel:closed` reasons include **`stop_reassigned`** (in the shared type + emit sites; the ARCHITECTURE
  table omits it) — the client handles it.
- The **pre-existing-damage ack has no customer-self-serve endpoint**: the as-built records it inside the
  staff inspection (`customerAck`/`ackBy`/`damagePhotoId`). The app therefore **surfaces** the flag +
  photo + ack state rather than re-submitting it. (If a true async customer ack is wanted later, that's a
  thin additive transition endpoint — deliberately not added this increment to avoid touching the proven
  inspection contract + its e2e.)
- **Approve has an expiry guard; decline does not** (only the SENT atomic claim) — the client treats both
  409s as server authority.
