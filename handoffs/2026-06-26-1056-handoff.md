## What shipped

### Shared data layer (reuse, no fork)
- Reuses **`packages/api-client`** unchanged: `ApiClient` (fetch + single-flight 401→refresh→retry +
  problem+json→ApiError) + `useAuthSession`. `apps/web/lib/api-client.ts` = `ConsoleApiClient extends
  ApiClient` adding the ops surface (orders/intake/quote, logistics/dispatch, fleet, media, finance).
- **Web token strategy** (`lib/token-store.ts`): access token **in memory only** + refresh in
  **localStorage** — the documented XSS trade-off. The httpOnly-cookie-BFF pattern is the recommended
  hardening but a FOLLOW-UP, because (1) the as-built `/auth/refresh` is body-based and the api-client
  assumes one base for all calls incl. refresh (cookie-refresh needs a separate Next-BFF origin →
  would fork the transport), and (2) the `WS /live/fleet` handshake already needs the access token
  readable in JS. Blast radius capped by Inc-2 server-side refresh rotation + reuse-detection + access-
  jti denylist + short TTL.
- `useAsync` (consistent loading/error/empty), `rbac.ts` (UI role groups mirroring §17.3), `session.tsx`
  (SessionProvider over a singleton client), `order-status.ts` (pure §5.1 timeline from server state).

## As-built ↔ prompt reconciliations (the code won)
- **Token strategy**: chose access-in-memory + refresh-in-localStorage (not httpOnly cookie) given the
  body-based `/auth/refresh` + the WS-needs-access-token-in-JS constraint; recommended cookie-BFF as a
  follow-up (documented in `lib/token-store.ts` + above).
- **addStop returns the created STOP, not the route** (server: `route.service.ts` `return stop`); the
  console + proof re-fetch the route after addStop. assign/optimize/publish return the full route.
- **§5.4 ops transitions are COLON-action routes** (`/route-stops/:id:depart` …); fail/skip require a
  reason. (The Inc-9 slash-route lesson was for the DRIVER surface; the ops controller uses colons.)
- **Client-rendered console** (not server components): the session/WS/api-client are browser-side and
  we're not using httpOnly cookies, so server components can't read the token. Standard for an
  authenticated dashboard.
