## Gotchas hit + fixed (so the next operator doesn't relive them) — see the runbook §4
- Fresh Railway volume has `lost+found` → set **`PGDATA` to a subdir** of the mount (this was the real cause of the early "can't reach Postgres" — Postgres was *crashing on init*, not a network fault).
- Railway private networking is **IPv6-only** → Postgres `listen_addresses=*`; ioredis **`REDIS_FAMILY=0`**.
- `railway volume add --service X` **panics** → `railway service link X` first, then `volume add --mount-path …` (no `--service`).
- `railway redeploy` replays the previous variable snapshot → to apply changed vars, set a var **without** `--skip-deploys`.
