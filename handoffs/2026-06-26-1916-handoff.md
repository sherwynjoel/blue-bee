## What shipped

A thin, **read-only**, RBAC-gated, **org-scoped** aggregation module + an Analytics console page — reusing the Inc-14a owner-KPI helpers (DST window / cents-exact money / on-time math) and the proven `scopedPrisma` org boundary. **No schema change, no writes** (mirrors the Inc-11 CatalogModule / Inc-14a OwnerModule additive read pattern).

### API — `apps/api/src/analytics/`
- `analytics-kpi.ts` — pure helpers (range parse + validation, divide-by-zero-safe `pct`/`ratio`, `median`, dwell, AR-aging bucket, week/month spans). Re-exports the owner-kpi money/on-time/window helpers — **no duplication.**
- `analytics.service.ts` — the aggregations over `scopedPrisma`. Each metric is computed in its own `try/catch` wrapper (`metric()`); Phase-2-only metrics return via `deferred()`.
- `analytics.controller.ts` — three `/v1` routes, problem+json, per-dashboard `@Roles`.
- `analytics.module.ts` — registered in `app.module.ts`.
- `analytics-kpi.spec.ts` — 20 pure-math unit tests (hand-computed expectations).
- `apps/api/test/analytics.e2e-spec.ts` — 13 e2e (real DB).

### Endpoints
| Method · Path | Roles | Returns |
|---|---|---|
| `GET /v1/analytics/operational?from&to` | OWNER, DISPATCHER, CSR, PLANT_OP, FINANCE | on-time pickup/delivery %, route adherence, stops/hour, avg dwell, failed/skip rate, items-lost rate, rewash rate, plant throughput (+ 2 deferred) |
| `GET /v1/analytics/commercial?from&to` | OWNER, FINANCE | tracked GMV, jobs + jobs/week, repeat rate, revenue/route, AR aging, quote→approval conversion + median hrs, damage-claim rate + median resolution (+ 2 deferred) |
| `GET /v1/analytics/accounts/:accountId/scorecard?from&to` | OWNER, FINANCE, CSR | loss rate, on-time %, monthly spend (+ 1 deferred); org-scoped (cross-org id → 404) |

`from`/`to` are optional ISO-8601 (default: last 30 days); invalid range → 400 problem+json. DRIVER (org-staff but self-scoped) and customers → 403.

## Honesty firewall — metric → source (computed vs deferred)

**Computed from real Phase-1 rows** (each traces to a query + a test; row counts shown in the evidence JSON below):

| Metric | Source query |
|---|---|
| onTimePickupPercent / onTimeDeliveryPercent | COMPLETED RouteStops (kind PICKUP/DELIVERY) with a `timeWindow`, completed ≤ window end |
| routeAdherencePercent | COMPLETED ÷ terminal (COMPLETED+FAILED+SKIPPED) RouteStops |
| stopsPerHour | COMPLETED stops ÷ Σ per-route active hours (last completedAt − first arrivedAt) |
| avgDwellMinutes | GeofenceEvent ARRIVED→DEPARTED per stop (fallback RouteStop arrivedAt→completedAt) |
| failedSkipRatePercent | (FAILED+SKIPPED) ÷ terminal RouteStops |
| itemsLostRatePercent | distinct Items with a LOSS Claim ÷ Items in range |
| rewashRatePercent | Orders currently in REWASH ÷ Orders in range (status snapshot; full reject/reclaim is B3.4 / Phase 2) |
| plantThroughput | Items reaching READY/DELIVERED in range + per-day |
| trackedGmv | Σ Order.totals.total over Orders created in range |
| jobCount / jobsPerWeek | Order rows created in range (÷ weeks) |
| repeatRatePercent | accounts with >1 Order ÷ accounts with ≥1 Order |
| revenuePerRoute | Σ totals of Orders on routes created in range ÷ routes |
| arAging | unpaid Invoices issued in range, outstanding = total − Σ succeeded payments, aged to range end |
| quoteApprovalConversionPercent / medianQuoteApprovalHours | non-DRAFT Quotes (APPROVED ÷ total; median approvedAt − createdAt) |
| damageClaimRatePercent | DAMAGE Claims ÷ Orders in range |
| medianClaimResolutionDays | RESOLVED Claims; resolution ≈ updatedAt − createdAt (Claim has no `resolvedAt` — exact SLA field is a Phase-2 add) |
| lossRatePercent / onTimePercent / monthlySpend (scorecard) | per-account variants of the above (Items / RouteStops / captured Payments via `order.accountId`) |

**Deferred — returned as `unavailable_in_phase_1` (value null), NOT shown, NEVER faked:**

| Metric | Why deferred |
|---|---|
| parStockoutIncidents | par levels / standing orders are Phase 2 (no stockout source in Phase 1) |
| ppoh (pieces/operator-hour) | no labour-hours / timeclock model to normalise per operator-hour |
| activeContracts | contracts / standing orders not modelled in Phase 1 |
| csat | no CSAT / satisfaction survey capture in Phase 1 |
| costCenterSplit (scorecard) | cost centres (wing/floor splits) are Phase 2 |

## QC gate (6-lens + audit-every-number, parallel read-only subagents)
- RBAC + org-scope: clean — every query goes through `scopedPrisma`; scorecard `findFirst` AND-merges the org boundary (cross-org → 404).
- Audit-every-number: every computed metric traces to a query + a test; all 5 deferred metrics justified (no Phase-1 source); no hardcoded/silent-zero values; no N+1 (each metric is O(1) queries).
- One MINOR finding **refuted**: a suggested avgDwell "multi-event overwrite" is impossible — `GeofenceEvent` has `@@unique([routeStopId, type])` (≤1 ARRIVED + ≤1 DEPARTED per stop).
