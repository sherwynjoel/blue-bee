### Admin API — `apps/api/src/admin/` (`/v1/admin/*`, `@Roles(OWNER)`, every mutation audited §8.7)
| Method · Path | Purpose |
|---|---|
| `GET /admin/users` | List org users with their role grants |
| `POST /admin/users/:userId/roles` | Assign a role grant (audited; org-scoped; ACCOUNT/SITE scopeId validated in-org; 409 on duplicate) |
| `DELETE /admin/users/:userId/roles/:roleId` | Revoke a grant (audited; **409 on last-OWNER**); returns reflected grants |
| `GET/POST/DELETE /admin/devices` | Device CRUD (audited; push tokens **masked** over the wire) |
| `GET /admin/drivers` · `PATCH /admin/drivers/:driverId` | List drivers · assign/clear default vehicle (audited) |
| `GET /admin/notification-config` | **Read-only** viewer of the live event→channel matrix (`templatesEditable:false`) |
| `GET /admin/audit-logs` | Query the immutable audit log (filter entity/entityId/actor/action/from/to; cursor-paginated; read-only) |

- **Reuse, not reinvent:** Vehicle/Driver CRUD already ships + is audited (Inc-4 logistics `/v1/vehicles` · `/v1/drivers`) and is **reused** — the admin surface adds only what was missing (roles, devices, driver→vehicle assignment, the two read-only viewers).
- **tx-scoping (carry-forward lesson) honored:** every write inside `$transaction` pins `org_id` explicitly (assigns via explicit `orgId`; revokes/deletes via `deleteMany`/`updateMany` with `{id, orgId}`) and audits in the **same** tx — the scoped extension doesn't reach inside a tx.
- The basic `GET /admin/users` was **moved** from `UsersController` → `AdminController` (same path/shape/gate — the existing auth e2e stays green).
