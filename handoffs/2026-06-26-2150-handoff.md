## What changed (before → after)

### 1. Stops/hour (and any ratio) display guard — honest, not a cover-up
- **New `apps/web/lib/ratio.ts`** — `guardRate(value, {max, unit})` + `guardStopsPerHour` preset (`MAX_PLAUSIBLE_STOPS_PER_HOUR = 100`, documented: a physical route stop takes minutes, so even an aggressive cadence is well under ~60/active-hour; 100 is generous enough never to suppress real data while catching the denominator-collapse artifact that lands orders of magnitude higher).
- **`apps/web/lib/format.ts`** — new `formatNumber()` (thousands separators, ≤2 decimals, trailing zeros trimmed, honest `—` for non-finite); `money()` now groups the integer part (decimals + sign preserved **verbatim** — presentation only, not a re-derivation).
- **`apps/web/components/AnalyticsHome.tsx`** — `Stat` gains an optional `guard`; `asNumber` now uses `formatNumber`. The "Stops / hour" tile uses `guardStopsPerHour`.
  - **Before:** `Stops / hour` rendered the raw computed `~195,652` (a real value, but meaningless — the e2e route-stops have `arrivedAt ≈ completedAt`, collapsing the on-site-hours denominator).
  - **After:** an implausible value renders **`n/a (insufficient data)`** (muted), keeps the `n=rowCount` line, and **discloses the raw figure + reason in the tile tooltip** ("Computed 195,652 stops/hr, which is implausibly high… shown as insufficient data rather than a misleading number"). A plausible value (e.g. `0.69`) still renders, now formatted.
  - **Honesty:** the guard states insufficient data plainly and never hides the underlying problem behind a fake-clean number. Existing `Metric`-level firewall (Phase-2 badges, `—` for no-rows) is untouched.
