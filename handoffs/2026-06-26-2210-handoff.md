## Delete-policy summary (the honesty firewall)
A hard `user.delete()` is **not** viable on this schema: `AuditLog` is append-only (a DB trigger blocks UPDATE/DELETE) and `AuditLog.actor_id` is `ON DELETE SET NULL`; deleting a user who has ever acted (incl. the deletion event itself) fires a SET-NULL update on the immutable log and aborts. `Driver → Shift/Route` are RESTRICT/retained business records. So the policy, in one `$transaction`:
1. **Purge** (hard delete): refresh tokens (all sessions), device tokens, devices, notifications, notification prefs, user roles (all access).
2. **Scrub** `Driver.license` → null (the Driver row is kept; shifts/routes reference it).
3. **Anonymize** the `User` row: `name`→`"Deleted user"`, `email`/`phone`→null, `authProviders`→[], `status`→`SUSPENDED`.
4. **Audit** with a non-PII summary.

Irreversible (no email/phone ⇒ no OTP login path; identities severed); audit trail preserved (a compliance control). Retained, no longer identifying: the anonymized user row + business/financial records (orders/invoices/payments/messages) per legal retention (PRD §12.4). Documented in `docs/COMPLIANCE.md` and the `account.service.ts` header.
