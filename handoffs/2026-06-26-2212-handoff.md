## What shipped
1. **Standing/recurring orders** — `StandingOrder` (org-scoped; `accountId`+`siteId`+`serviceId`, cadence `WEEKLY`|`BIWEEKLY` + `weekday` + `pickupWindow`, `concierge`, `active`, `startsOn`/`endsOn`, `nextRunAt`/`lastRunAt`) + `StandingOrderOccurrence` idempotency ledger (unique `(standing_order_id, period_key)`). Pure cadence math in `recurring-schedule.ts` (DST-safe — whole-day UTC arithmetic; biweekly parity from the anchor).
2. **Generation job** — `StandingOrderGenerationService`. Materializes DUE standing orders (bounded look-back window) into real `Order`s (`type=ROUTE_STOP_ORDER`, `REQUESTED`, pickup window from the occurrence). **Idempotent**: an `INSERT … ON CONFLICT (standing_order_id, period_key) DO NOTHING RETURNING` claim (Inc-5) → a re-run/concurrent pass materializes nothing new. **Tenant-confined**: the `run` endpoint pins the caller's `org_id`; the (env-gated, default-off) background scan serves all orgs. Concurrent calls serialize in-process via a promise chain.
3. **Recurring route auto-gen** — reuses the **Inc-4 PostGIS `OptimizerService.sequence`** + two-phase reseq. **Graceful degradation**: orders commit in their own per-occurrence transaction BEFORE routing; a route-create or sequencing failure is caught (counted in `routeFailures`), leaving the generated orders intact (route stays unoptimized / `occurrence.routeId` null). The optimization itself is audited.
4. **Concierge handoff** — `RouteStop.stopKind` (`RouteStopHandoff` `DIRECT`|`CONCIERGE`), **orthogonal** to `kind` (pickup/delivery). Generated concierge pickups are `CONCIERGE` (single building-handoff point).
5. **Per-account billing terms** — `Account.billingMode` (`PER_ORDER`|`BATCH_PERIODIC`) + `billingNetDays`. The batch/periodic path (`AccountBillingService`) batches a period's billable orders (those with a total, not already invoiced) into **ONE** `Invoice` (+ `InvoiceLine`s, net-days due), **idempotent per (account, period)** via a deterministic invoice number. `PER_ORDER` accounts reject batch (400). **Cost-center split billing stays deferred** (`Invoice.costCenterBreakdown` modeled-but-empty).
6. **Seed timestamp fix** — added a clearly-labelled COMPLETED demo route (4 stops, distinct realistic 12–23 min on-site spans, one CONCIERGE) → analytics **stops/hour 1.44, avg dwell 16.3 min**. Root cause of the Inc-15 `~195,652` anomaly: the §5.4 state machine stamps `arrivedAt`/`completedAt` back-to-back via `new Date()`, so API-completed stops sit ms apart → `Σ(lastCompleted−firstArrived) ≈ 0` → degenerate `stops/hour`. The fix is at the data source (a freshly-seeded demo tenant now has realistic spans). The Inc-15 analytics e2e fixture already used realistic timestamps (untouched).
