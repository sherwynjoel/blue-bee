## What shipped
The recorded **Track-A condo follow-on** — the operator-facing **B2B account-management console** in `apps/web` over the now-merged condo endpoints, plus **one thin additive API read**. The B2B wedge: list + detail of building accounts, FULL standing/recurring-order management, the generated-orders feed, per-account billing terms, batch/periodic invoicing, and the B2B scorecard. ## API — the ONE new read (apps/api/src/accounts; thin, read-only, scopedPrisma, RBAC, problem+json, NO schema change, not audited)
- `GET /v1/accounts` — cursor-paginated directory: `id, name, type, billingMode, billingNetDays, siteCount, activeStandingOrderCount` (active count via a **filtered `_count`** — single query, no N+1).
- `GET /v1/accounts/:accountId` — detail header + the account's `sites` (one filtered-`_count` query). Cross-org id → **404**.
- Roles: OWNER/FINANCE/DISPATCHER/CSR. New `AccountsModule` (1-line `app.module.ts` registration). Distinct GET routes — **no collision** with the recurring `account-billing.controller`'s `:accountId/{billing-terms,invoices/batch,generated}` or the deletion `@Controller('account')` (singular).

## Web (apps/web)
- **Accounts** nav entry (RBAC-gated `can.accounts`) → **AccountsHome** list (name · type · billing mode · net-days · sites · active standing orders; rows link to detail).
- **AccountDetail** sections:
  - **Scorecard** — reuses `GET /v1/analytics/accounts/:id/scorecard` (Inc-15); honest `Metric` tiles (cost-center split → **"Phase 2"** badge, never faked; null → "—").
  - **Standing / recurring orders — FULL management** — list + create / pause-resume(edit) / delete via the existing T1 endpoints; cadence/weekday/pickup-window/concierge/active shown; **"Run due generation (org-wide)"** honestly labelled (`POST /v1/standing-orders/run` is org-confined but materializes ALL the org's due standing orders, not one account).
  - **Generated orders & routes** — `GET /v1/accounts/:id/generated`.
  - **Billing** — view + edit terms (PER_ORDER | BATCH_PERIODIC + net-days, `PUT /v1/accounts/:id/billing-terms`); **batch/periodic invoice** (`POST /v1/accounts/:id/invoices/batch`) over a period window → renders the created invoice (lines + total + due). Batch form shown only for BATCH_PERIODIC (else an honest note); the server's 400 (`not_batch_account`) surfaces via `ApiError`.
  - RBAC UI mirrors the server (UX-only; server authoritative): finance actions OWNER/FINANCE; SO writes OWNER/DISPATCHER; reads ops/finance. Loading / empty / error on every section.
- `apps/web/lib/api-client.ts` — typed methods for all of the above; base `HttpMethod` gained `PUT` (additive, `packages/api-client`).
