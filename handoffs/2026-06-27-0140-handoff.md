## API — three thin account-scoped reads (apps/api/src/accounts — `AccountsPortalService`/`Controller`; read-only, `scopedPrisma`, RBAC, problem+json, NOT audited)
Roles **OWNER/FINANCE/DISPATCHER/CSR** (mirrors the directory reads). Every read first proves the account is in the principal's org (`assertAccountInScope` → **404** for a cross-org id), then confines the query to that ONE account. Routes are distinct sub-paths — no collision with the directory (`/accounts/:id`) or the recurring module's `/accounts/:id/{billing-terms,invoices/batch,generated}`.

- `GET /v1/accounts/:accountId/orders` — **DELEGATES to the proven `OrdersService.listOrders`** with an additive optional `accountId` filter on `listOrdersQuerySchema` + the where-clause (existing row-scope + cursor preserved). No duplicated listing logic. `OrdersService` is now **exported** from `OrdersModule`; `AccountsModule` imports `OrdersModule`. (The additive filter also makes `GET /v1/orders?accountId=` work for free.)
- `GET /v1/accounts/:accountId/manifests` — a **read-only VIEW** of the account's route-stop manifests (`Manifest` where `routeStop.accountId = account`, one query with `routeStop`+`site` include → **no N+1**). Summary fields only (stop seq/status/kind, order ref, site, `expectedItemCount` parsed from the manifest lines). **Never generates** — generation stays on the route/stop endpoints.
- `GET /v1/accounts/:accountId/exceptions` — the owner exceptions feed **scoped to the account** (failed/skipped stops, held orders, open disputes, failed payments). Reuses the **shared** status sets + the `OwnerException` shape.

### Reuse, not copy-paste (the extraction the prompt asked for)
- Extracted `EXCEPTION_LOOKBACK_MS`, `EXCEPTION_FEED_LIMIT`, `EXCEPTION_STOP_STATUSES`, `OPEN_DISPUTE_STATUSES`, and the `normalizeExceptions()` row→`OwnerException[]` shaper to **`apps/api/src/common/exceptions-feed.ts`**. `OwnerService.exceptions` (Inc-14a) now imports them — the magic values live in ONE place; the org-wide owner feed and the account-scoped portal feed differ ONLY in their WHERE. The owner refactor preserves exact behavior (owner e2e green).
- **Account attribution (isolation-critical):** stops/payments match via direct `accountId` **OR** the related `order.accountId`; held orders via direct `accountId`; disputes — which have **no `order` relation in the schema** — via their `payment` → (`accountId` | `order.accountId`). A row with no account-bearing link is safely **under-included** (better than leaking another account's row). Proven isolated bidirectionally in the e2e.
