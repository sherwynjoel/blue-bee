## Schema (additive migration `20260626200616_track_b_resident_clothing`)
Only `CREATE TYPE` (GarmentStatus/ResidentStatus/LostFoundStatus), `CREATE TABLE` (Resident, LostFoundItem), `ADD COLUMN` (Item.residentId, Item.garmentStatus, CustodyEvent.garmentStage), and **two `DROP NOT NULL` relaxations** (`Item.orderId`, `CustodyEvent.stage`) — **no `DROP TABLE/COLUMN`, no data loss**. Existing rows keep their values; new nullable columns default null.
- **`Item.orderId` is now nullable** — a resident garment is owned by the RESIDENT (`residentId`), not an order (orderId null). Ripple checked: ONE Item-creation site (orders.service book flow, always sets orderId) and NO `item.order` non-null deref, so the relation going optional is safe.
- `CustodyEvent` gains `garmentStage GarmentStatus?` (and `stage` nullable) — a garment custody event sets `garmentStage`, a specialty one sets `stage`. Append-only preserved (insert-only).
- New enum values `GARMENT`/`LINEN` (ItemKind) + `RESIDENT` (TagBinding) were **already present** in the schema.

## API (apps/api/src/residents — RBAC, problem+json, org/site-scoped, NOT audited-exempt)
- **Resident directory** — `POST /v1/residents` (create), `GET /v1/residents?siteId=` (list), `GET /v1/residents/:id` (detail), `GET /v1/residents/:id/clothing` (A4.2 buckets). RBAC: reads → ops (OWNER/CSR/PLANT_OP) + the account's own ACCOUNT_ADMIN/ACCOUNT_STAFF (their site only); create → OWNER/CSR/ACCOUNT_ADMIN. **EVERY user-facing resident-PII read writes an immutable AuditLog row** (RESIDENT_READ / RESIDENT_LIST_READ / RESIDENT_CLOTHING_READ) — §12.2.
- **§5.2-B garment lifecycle** — `POST /v1/residents/:id/garments` (enroll → GARMENT_ENROLLED), `POST /v1/garments/:id/transition` (linear advance), `POST /v1/garments/:id/lost-found` (RETURN_SORT → LOST_FOUND_POOL). Plant ops (OWNER/CSR/PLANT_OP). Each move = a **compare-and-swap on the from-state inside a `$transaction`** + an **append-only CustodyEvent(garmentStage)**; illegal transition → **409**, a branch target via `/transition` → **400** (use the dedicated endpoint). `canTransitionGarment` (shared) is the single guard.
- **Lost & found** — `GET /v1/lost-found?siteId=` (OPEN pool, audited), `GET /v1/lost-found/report?siteId=` (open/reconciled counts + items, audited), `POST /v1/lost-found/:id/reconcile` (LOST_FOUND_POOL → RECONCILE). Reconcile **enforces same-site** + uses an **atomic CAS gate** (OPEN→RECONCILED) so two callers can't double-reconcile, then CAS the garment out of the pool.
