## Deliberate engineering decisions (reversible at merge — flagged for the founder)

1. **Motion via React Native `Animated`, not `react-native-reanimated`.** Reanimated needs a babel plugin + worklet jest setup that is the single biggest risk to the "keep jest-expo green on the flaky external drive" hard constraint. RN `Animated` springs deliver the same press-scale (.97) / sheet / toast / skeleton feel with **zero** test-graph risk. The baseline already exercised `Animated` under jest-expo green. Swap to reanimated at merge if desired — the kit isolates all motion.
2. **Added `expo-haptics` (`~13.0.1`, the SDK-51 pin)** to both apps (central to the operator brief; trivially mocked in jest). The only new dependency.
3. **Icons: `@expo/vector-icons` (Feather), one family** — already installed (no new native dep, no `react-native-svg`). It is **jest-mocked** in `jest.setup.js` because importing it pulls `expo-font`'s native font loader, which doesn't load under Node (the real icons ship in the device bundle — confirmed: `expo export` bundles the Feather fonts).
4. **The kit reads safe-area insets resiliently** (`SafeAreaInsetsContext ?? zeros`) so `Screen`/`Sheet`/`Toast` never throw in the screen tests that render bare (no `SafeAreaProvider`).
5. **Notification accent color** in both `app.json` updated `#1f6feb` → Daylight azure `#0B5FFF` (cosmetic only; push behavior unchanged).
