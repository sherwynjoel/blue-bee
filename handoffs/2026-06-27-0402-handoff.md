## What shipped — the #1 pending condo/B2B item

Cost-centre split billing is now **real** (PRD §B4.1 hierarchy, §A5.2 splits, §B5.2 export, §8.4 billing). A condominium stays **ONE `BUSINESS` Account → Sites (towers) → Cost Centres (the billing groups)** — additive to the proven Account→Site model, **not** a parent-of-accounts. `Invoice.costCenterBreakdown` (a previously-unused JSON column) is now populated by the batch-invoice engine and surfaced on the invoice read.

### Endpoints (all org-scoped, problem+json, audited)
| Method + path | RBAC | Purpose |
|---|---|---|
| `POST /v1/accounts/:accountId/cost-centers` | OWNER/FINANCE | Create (unique `code` per account → 409; cross-org account → 404; site-from-another-account → 400) |
| `GET /v1/accounts/:accountId/cost-centers?active=` | OWNER/FINANCE/DISPATCHER/CSR | List (ordered by code) |
| `PATCH /v1/cost-centers/:id` | OWNER/FINANCE | Rename / re-classify (`kind`) / activate-deactivate (`code` immutable) |
| `PUT /v1/orders/:id/cost-center` | OWNER/FINANCE/DISPATCHER/CSR | Attach `{costCenterId}` or detach `{null}` — cost centre must match the order's account (else 400); cross-org order → 404 |
| `GET /v1/accounts/:accountId/cost-centers/report?from=&to=` | OWNER/FINANCE/DISPATCHER/CSR | Per-cost-centre totals over the window (orders by created-at) + Unassigned bucket + grandTotal |
| `GET /v1/accounts/:accountId/cost-centers/report.csv?from=&to=` | OWNER/FINANCE/DISPATCHER/CSR | §B5.2 export — real `text/csv` attachment bytes (RFC-4180 escaped), account-scoped |

Standing orders accept `costCenterId` on create/edit (validated to belong to the account) and **propagate it to generated orders** (so a generated order, once priced + batch-invoiced, lands in the right split automatically). `GET /orders/:id/invoice` and the batch-invoice response both surface `costCenterBreakdown` (empty `[]` for an un-split / single-order invoice).

### Split-billing logic (the core)
`recurring/account-billing.service.ts → generateBatchInvoice` now, after building the per-order billable lines (integer cents):
1. selects each order's `costCenterId`,
2. resolves `{code, name}` for the referenced centres (scoped to the account),
3. calls the pure, unit-locked `buildCostCenterBreakdown(lines, meta)` (`cost-centers/cost-center-split.ts`) which **partitions the lines by `costCenterId`** (null → an explicit **"Unassigned"** bucket, always last; named centres ordered by code) and renders `[{costCenterId, code, name, subtotal, tax, total}]`,
4. writes that array to `Invoice.costCenterBreakdown`, tags each `InvoiceLine.cost_center_id`, and audits `costCenterCount`.

Because the partition is an exact integer-cents split of the same lines, **Σ split subtotal/tax/total ≡ invoice subtotal/tax/total** (no rounding leak — test-locked at cents). **HST is taken verbatim from each order's `totals` (derived upstream by the quote engine) — never re-derived or hardcoded here.** Idempotency is preserved end-to-end: a re-run hits the deterministic `(account, period)` short-circuit / the P2002→return-existing path and the breakdown is byte-stable.

### Migration (additive, reversible)
`20260626214353_cost_centers` — **only** `CREATE TYPE "CostCenterKind"`, `CREATE TABLE "CostCenter"`, three nullable `ADD COLUMN "cost_center_id"` (Order / StandingOrder / InvoiceLine), indexes, and `SET NULL` FKs. **No DROP / no destructive op.** `CostCenter` is `Account`-CASCADE; the three attribution FKs are `SET NULL` (a deleted centre falls its orders into "Unassigned" — never lost). Unique `(account_id, code)`. Generated with `prisma migrate dev` — the shadow DB **replayed the entire chain (incl. Track B) cleanly**, and `prisma db seed` runs clean against the new schema.

## Worked example (from the e2e — a condo invoice split across Tower A / Tower B / Amenity)
Five DELIVERED orders on one `BATCH_PERIODIC` condo account, batch-invoiced over June 2026:

| Cost centre | orders | subtotal | tax (HST) | total |
|---|---|---|---|---|
| Amenity (AMEN) | 1 | 75.25 | 9.78 | 85.03 |
| Tower A (TWR-A) | 2 | 150.05 | 19.51 | **169.56** |
| Tower B (TWR-B) | 1 | 200.00 | 26.00 | 226.00 |
| **Unassigned** | 1 | 40.40 | 5.25 | 45.65 |
| **Invoice total** | 5 | **465.70** | **60.54** | **526.24** |

Σ splits = 465.70 / 60.54 / 526.24 = invoice subtotal / tax / total — **cents-exact**. A re-run returns the same invoice id with an identical breakdown. The CSV export of the same period reconciles to a `TOTAL` row of `526.24`.
