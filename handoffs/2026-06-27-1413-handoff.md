## What this is
The last real Phase-1 gap: **proof of delivery**. Before this, a driver could walk a stop through §5.4 (`…/complete`) but captured **no delivery evidence**. Now, at a DELIVERY stop, the driver captures a delivery **photo** + a **signature** + the device **geo**, uploaded via the proven Increment-10 media path, written to the existing 1:1 `ProofOfDelivery` row. This completes "book → track → custody → **deliver**".

## Migration — NONE needed
The schema was already POD-ready: `ProofOfDelivery` has `signatureKey?`, `geo`, `capturedBy?`, `routeStopId @unique` (1 POD per stop); `Photo` has `podId` + the `pod` relation (since `init_phase1`); `PhotoKind.POD` exists; `signatureKey` was added in `media_storage_inc10`. `prisma migrate status` = **"Database schema is up to date!"** (13 migrations, none new).

## Backend (`apps/api`) — additive, isolated
### 1) Driver-scoped POD media authorization (the key integration point)
The customer `/v1/media` presign authorizes via `OrderAccessService.requireOrderForWrite` — a driver is **not** the order's account-writer, so that path can't serve a driver. New methods on **`MediaService`** — `presignForStop(principal, orderId, dto)` + `confirmForStop(principal, storageKey, expectedOrderId)` — reuse the EXACT Inc-10 mechanics (`assertContentType` allow-list, size, unguessable org-namespaced key `org/<org>/pod/<uuid>.<ext>`, `headVerify` of the real object's content-type+size with bad-object delete, idempotent-on-key, `MediaSigner` signed reads) but **skip** `OrderAccessService` (the DRIVER layer already proved stop-ownership) and instead cross-check `intent.orderId === the stop's order` **and** `intent.kind === POD`. So:
- The **customer presign/confirm are byte-unchanged** — no widened hole (QC media-security lens: clean).
- A key presigned for another stop/order/kind → **400** `pod.media_not_confirmed` (no smuggling — e2e-locked).

### 2) POD endpoints (`DriverController`, `@Roles(DRIVER)`, slash sub-paths)
- `POST /v1/driver/stops/:id/pod/presign` `{contentType, byteSize}` → `PresignMediaResult`.
- `POST /v1/driver/stops/:id/proof-of-delivery` `{signatureStorageKey, photoStorageKeys[1..], geo?{lng,lat}}` → `ProofOfDeliveryView`. `DriverService.captureProofOfDelivery`: `requireOwnStop` (route.driverId + org) → guard kind∈{DELIVERY,BOTH} + order present → `confirmForStop` each key (HEAD-verify, idempotent) → **`upsert` the POD on the unique `routeStopId`** + link the photo(s)+signature (set `podId`) + write `geo` (raw `ST_SetSRID(ST_MakePoint(lng,lat),4326)`) + `capturedBy`/`capturedAt` + audit, atomically. **Idempotent** — re-submit yields the same row, no dup photos.
- `GET /v1/driver/stops/:id/proof-of-delivery` → the POD view (signed reads; the signature is the photo whose key === `signatureKey`, the rest are delivery photos). `capturedBy = principal.userId`.

### 3) Delivery-complete gate — the documented choice
A DELIVERY/BOTH stop **cannot `complete` until a POD exists**. The gate lives in the **DRIVER layer** (`DriverService.stopAction`, before delegating `complete`) → a clean **400** `pod.pod_required` **before** the §5.4 machine is entered (never a half-applied transition). **Why the driver layer, not `RouteStopService`:** keeps the §5.4 graph + `RouteStopService`/`RouteStopStateMachine` **byte-unchanged**, the ops `/v1/route-stops` complete an **admin-override escape hatch** (ungated), and **pickup stops unaffected**. The driver is the real-world actor completing deliveries.

New shared contract: `packages/shared/src/proof-of-delivery.ts` (`presignPodMediaSchema`, `captureProofOfDeliverySchema`, `ProofOfDeliveryView`, `POD_ERRORS`).

## App (`apps/driver`)
- **`ApiClient`** — `presignPodMedia` / `captureProofOfDelivery` / `getProofOfDelivery`.
- **`src/media/pod-capture.ts`** — the REAL pipeline: `pickDeliveryPhoto` (camera via `expo-image-picker`), `signatureToAsset` (signature base64 PNG → real file via `expo-file-system`), `uploadPodObject` (validate → presign → PUT real bytes via `FileSystem.uploadAsync`), `oneShotGeo` (foreground `expo-location`, **optional** — tolerates denial), `capturePod` (upload photo+signature → POST POD).
- **`src/screens/PodScreen.tsx`** — Daylight-styled: take photo → sign (`react-native-signature-canvas`) → "Capture proof & complete" → captures geo → uploads → POST POD → **then** `doStopAction('complete')` (server-authoritative). A failure shows an error and **keeps the inputs** for retry (the POD is idempotent; `podCaptured` guards against re-upload on a complete-only retry); the §5.4 complete is **never faked locally**.
- **`StopScreen`** routes a DELIVERY/BOTH stop's `complete` to the POD screen (pickup completes directly, unchanged). Registered in `navigation.ts` + `App.tsx`.
- **Signature = PNG** (`react-native-signature-canvas` + `react-native-webview`) — chosen so the media allow-list stays PNG-only (no SVG → no XSS surface). React stays **18.2.0** (override held); lockfile delta = only the 4 POD deps.

### Offline tolerance (honest)
There is **no durable action outbox** in the app today (the only outbox is the in-memory GPS `LocationOutbox`). POD tolerance = **retry-in-screen + server idempotency + never fake a local complete** (a failed upload/POST surfaces an error; a 409 re-syncs). A durable cross-relaunch queue for stop actions/uploads remains the app's existing deferred item.
