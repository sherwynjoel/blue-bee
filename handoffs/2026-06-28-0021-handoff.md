## Models (additive migration `20260627180014_care_home_linen_par`)
- **`ParLevel`** — per (site, optional cost-centre) × linen SKU → `targetQty`. Unique per
  (site, cost-centre?, sku) via a **`NULLS NOT DISTINCT`** index (PG15+) so a site-level (NULL cost-centre)
  par is still unique. FK account/site/cost-centre Cascade, service Restrict.
- **`LinenStock`** — the on-hand **cache** per (site, cost-centre?, sku); same NND key; maintained
  atomically alongside each movement. **Invariant: `on_hand == Σ(LinenMovement.qty)` for the cell, always.**
- **`LinenMovement`** — the **append-only ledger** (signed qty: SOIL_PICKUP −, DELIVERY +, ADJUSTMENT ±).
  A DB trigger `linen_movement_append_only` (reuses `bluebee_block_mutation`) blocks UPDATE/DELETE.
  Parent refs are **scalar columns with NO FK relations** (the `StandingOrderOccurrence` idempotency-ledger
  precedent) — so no cascade ever fires the (correctly-refusing) append-only trigger.
- **`SoilPickup`** — the operational header the account sees ("N carts at HH:MM"): cart/bag count + weight +
  soiled + per-SKU `lines` + optional `routeStopId`. Mutable (not the ledger).
- **`Manifest`** (reused, additive cols) — `kind` (`PICKUP_CHECKLIST` default → existing specialty manifests
  unchanged; `PACK_TO_PAR` new) + nullable `siteId`/`costCenterId` + relations. The pack-to-par load sheet.

**Atomicity / concurrency:** every movement goes through `applyMovement` → a per-cell
`pg_advisory_xact_lock` (serializes the cell) → append the ledger row → `INSERT … ON CONFLICT
(site_id,cost_center_id,service_id) DO UPDATE SET on_hand = on_hand + EXCLUDED.on_hand` (atomic, commutative).
`ADJUSTMENT` reads the locked current and applies `delta = target − current`, so on-hand lands exactly on the
target **idempotently** while the ledger stays reconcilable.

## Endpoints (`/v1`, problem+json, scopedPrisma + audit-in-tx)
| method · path | roles | purpose |
|---|---|---|
| POST `/sites/:siteId/par-levels` | OWNER/CSR | set (upsert) a par target |
| GET `/sites/:siteId/par-levels` | ops + ACCOUNT_ADMIN/STAFF | list (account staff → own sites only) |
| PATCH `/par-levels/:id` | OWNER/CSR | update target |
| GET `/sites/:siteId/linen-stock` | reads | on-hand |
| POST `/sites/:siteId/linen-stock/adjust` | OWNER/CSR/PLANT_OP | set on-hand to an absolute target (ADJUSTMENT) |
| POST `/sites/:siteId/soil-pickups` | OWNER/CSR/DISPATCHER | record a pickup → CustodyEvent + SOIL_PICKUP movements + decrement |
| GET `/sites/:siteId/soil-pickups` | reads | pickup history (the account's confirmation feed) |
| POST `/driver/stops/:stopId/soil-pickup` | DRIVER | driver self-scope (route.driverId verified) |
| GET `/sites/:siteId/pack-to-par` | reads | live gaps = max(0, par − on-hand) per SKU |
| POST `/sites/:siteId/pack-to-par` | OWNER/CSR/DISPATCHER | snapshot the gaps into a PACK_TO_PAR Manifest |
| GET `/sites/:siteId/pack-to-par/manifests` | reads | generated load-sheet history |

Tenancy: `ParLevel`/`LinenStock`/`LinenMovement`/`SoilPickup` added to scoped-prisma `ACCOUNT_DIRECT` +
`SITE_DIRECT` → an account principal sees ONLY its own sites' rows; a cross-account site/id → **404**.
Manifest reads are gated by the scoped `requireSite` resolution (the cost-centre-report pattern), e2e-locked.
